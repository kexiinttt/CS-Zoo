# Lambdaessence

C++ lambda is essentially an anonymous class object generated by the compiler, that is, a **closure object**.

```cpp
auto f = [x](int y) {
    return x + y;
};
```

It can be roughly understood that the compiler generates a class similar to the following:

```cpp
class __Lambda {
private:
    int x_;  // 捕获的变量成为 closure object 的成员

public:
    __Lambda(int x) : x_(x) {}

    int operator()(int y) const {
        return x_ + y;
    }
};

auto f = __Lambda{x};
```

So lambda is not a "function" but a **callable object**. It can be called because it overloads `operator()`.

---

# Basic syntax of Lambda

```cpp
[capture](parameters) specifiers -> return_type {
    body
};
```


```cpp
[]      // 捕获列表
()      // 参数列表
mutable // 可选修饰符
noexcept // 可选异常说明
-> T    // 可选返回类型
{}      // 函数体
```

# Capture method

### Do not capture

No external variables are captured. This lambda can be implicitly converted to a normal function pointer:

```cpp
auto f = [](int x) {
    return x * 2;
};
```


```cpp
int (*fp)(int) = [](int x) { return x * 2; };
```

But as long as there is capture, it cannot be converted into a function pointer.

### Capture by value

Capture by value copies variables into the closure object when the lambda is created.
> Modification after creation will not affect the value stored inside the lambda.

```cpp
int x = 10;
auto f = [x] {
    return x;
};

x = 20;
std::cout << f(); // 10
```


```cpp
class __Lambda {
    int x_;
public:
    __Lambda(int x) : x_(x) {}
    int operator()() const { return x_; }
};
```

### Capture by reference

When capturing by reference, the lambda internally refers to the external variable itself. It can see subsequent changes to external variables.

```cpp
int x = 10;
auto f = [&x] {
    return x;
};

x = 20;
std::cout << f(); // 20
```


```cpp
class __Lambda {
    int& x_;
public:
    __Lambda(int& x) : x_(x) {}
    int operator()() const { return x_; }
};
```


> [!IMPORTANT]
> Pay attention to life cycle issues:
> ```cpp
> std::function<int()> bad() {
>     int x = 10;
>     return [&x] {
>         return x; // dangling reference
>     };
> }
> ```
> Here `x` has been destroyed after the function returns, the lambda holds a dangling reference, and the call is undefined behavior.

### Default capture

```cpp
[=]  // 默认按值捕获使用到的外部变量
[&]  // 默认按引用捕获使用到的外部变量
```

# Lambda default `operator() const`

By default, the call operator generated by lambda is `const`.


```cpp
int x = 10;

auto f = [x]() -> int {
    // x++; // 编译错误
    return x;
};
```


```cpp
class __Lambda {
private:
    int x_;

public:
    int operator()() const {
        // x_++; // 错，因为 operator() 是 const 成员函数
        return x_;
    }
};
```

Note that `const` here limits the members of the closure object itself, that is, the copy captured by value. Therefore, variables captured by value cannot be modified within the lambda by default.

---

# `mutable`: Copies captured by value can be modified

If you want to modify the copy captured by value, you need to use `mutable`:

```cpp
int x = 10;

auto f = [x]() mutable {
    x++;
    return x;
};

std::cout << f(); // 11
std::cout << f(); // 12
std::cout << x;   // 10，外部 x 不变
```

Equivalent understanding:

```cpp
class __Lambda {
private:
    int x_;

public:
    int operator()() {
        x_++;
        return x_;
    }
};
```

The effect of `mutable` is to turn `operator() const` into something other than `const operator()`.

Instead of making the external variable mutable, it allows the lambda to modify its own internal copy.

---

# External variables can be modified when capturing by reference

```cpp
int x = 10;

auto f = [&x]() {
    x++;
};
```

Although `operator()` is still `const` by default, what is modified here is not the member of the closure object itself, but the external object pointed to by the member reference.

```cpp
class __Lambda {
private:
    int& x_;

public:
    void operator()() const {
        x_++; // OK，引用本身不可重新绑定，但引用指向的对象可以修改
    }
};
```

---

# Capture `const` variable

```cpp
const int x = 10;

auto f = [x]() mutable {
    // x++; // 仍然编译错误
};
```

Even if `mutable` is added, if the captured member itself is `const int`, it still cannot be modified.

Because `mutable` only removes `const` from `operator()`, but does not remove `const` from the variable itself.

# Initialized capture (generalized capture)

Initialize capture:

```cpp
auto f = [x = 42] {
    return x;
};
```

Mobile capture:

```cpp
std::unique_ptr<int> p = std::make_unique<int>(10);

auto f = [p = std::move(p)] { // unique_ptr 无法按值传递，因为无法拷贝
    return *p;
};
```

Expression capture:

```cpp
auto f = [value = expensive_compute()] {
    return value;
};
```

# Lambda captured with `this`

In the member function:

```cpp
class Foo {
private:
    int x = 10;

public:
    auto getLambda() {
        return [this] { // 捕获的是当前对象指针
            return x;
        };
    }
};
```

⚠️ If the object has been destroyed, accessing `this` again in the lambda will be a dangling pointer.

You can use `[*this]` to capture a copy of the current object, but it will involve copying and you need to pay attention to performance.

```cpp
auto getLambda() {
    return [*this] { // 捕获的是当前对象的副本
        return x;
    };
}
```

# `auto`

The lambda parameter can be written `auto`, which is equivalent to creating a `operator()` function with a template.

```cpp
auto add = [](auto a, auto b) {
    return a + b;
};

add(1, 2);       // int
add(1.5, 2.5);   // double
```


```cpp
class __Lambda {
public:
    template <typename T, typename U>
    auto operator()(T a, U b) const {
        return a + b;
    }
};
```
